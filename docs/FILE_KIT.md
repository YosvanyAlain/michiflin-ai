# Kit de archivos / File kit

## Español

Abre **Descargas → Kit de archivos**. Elige **En este dispositivo** para trabajar sin conexión con copias guardadas dentro de esa instancia de la miniapp, o **Servidor temporal** para trabajar en el espacio del usuario autorizado. Los originales elegidos en el teléfono no se modifican ni se borran.

### Organizar y editar

- Toca la flecha de una carpeta para expandirla o contraerla; toca su nombre para convertirla en destino. El árbol se desplaza en horizontal y vertical para mostrar los nombres completos. Marca las casillas individualmente o usa **Seleccionar todo en la carpeta actual**; las selecciones de otras carpetas se conservan.
- Puedes crear carpetas, renombrar, copiar o preparar un movimiento y pegar en la carpeta elegida. Al renombrar varios elementos, elige prefijo, sufijo, reemplazo literal o numeración, revisa la vista previa y confirma. Las extensiones se conservan en los modos de sufijo y numeración. Una colisión o selección solapada rechaza el lote sin reemplazar nada.
- Eliminar pide confirmación y solo afecta a las copias del espacio activo. Deshacer y rehacer recuperan operaciones, incluido el lote de renombrado, mientras se conserve el historial. **Vaciar historial** elimina la posibilidad de recuperar versiones anteriores, no los archivos visibles.
- Toca un archivo para previsualizar texto UTF-8, imágenes o medios compatibles con el cliente. Guarda el texto con el botón correspondiente. Si el archivo cambió en otra ventana, la escritura se rechaza en lugar de sobrescribir la versión nueva. Otros binarios se pueden exportar y abrir con otra aplicación; no hay editor hexadecimal, recorte ni conversión multimedia.
- El editor local admite hasta 4 MiB de texto. Las previsualizaciones remotas admiten hasta 200.000 bytes y la edición remota hasta 70.000 bytes por solicitud. Para archivos mayores, envía una copia al chat o expórtala para abrirla fuera.

### Comprimidos y partes

Selecciona archivos o carpetas y elige **Crear ZIP o 7z**. Puedes establecer una contraseña y un tamaño de volumen; `0` significa un único archivo. Para abrir ZIP, 7z o RAR, selecciona todas las partes y señala la primera. La extracción crea una carpeta nueva y no reemplaza archivos existentes. RAR es solo de lectura. No se garantiza que todas las variantes de RAR, contraseñas, compresión o multipartes funcionen en todos los clientes.

En el móvil, el motor opera en un Worker con recursos locales y un presupuesto ajustable de 16–128 MiB para entrada y salida; el bloqueo de red externa depende del cliente WebXDC. El consumo real de memoria puede ser mayor; aumenta el presupuesto con cautela porque el teléfono puede cerrar la app. La extracción local con 7-Zip WebAssembly es de todo el contenido, no selectiva.

**RAR selectivo en el servidor:** selecciona el `.rar` o todas las partes genuinas `.part1.rar`, `.part2.rar`…, señala la primera y pulsa **Ver contenido y elegir**. Después marca los archivos concretos y extrae a una carpeta nueva. Las carpetas vacías no se recrean. Si los nombres del RAR no están cifrados, poder verlos no demuestra que la contraseña sea correcta; se comprueba al extraer. Una contraseña incorrecta y datos cifrados dañados no siempre se pueden distinguir. Enlaces simbólicos o duros, rutas inseguras y nombres duplicados se rechazan. Una contraseña diferente por cada entrada puede requerir extracciones separadas.

El lector nativo usa UnRAR oficial **7.30 beta 2**, con licencia separada y fuente incluida en `vendor/unrar`. Es solo para descomprimir y deberá actualizarse cuando haya una versión estable o avisos de seguridad aplicables. La entrada y los archivos seleccionados se procesan por bloques, no se cargan íntegros en RAM. Un proceso temporal sin red y con permisos reducidos rechaza la operación si no puede aislarse, pero ningún sandbox garantiza ausencia de vulnerabilidades. Los archivos sólidos pueden exigir procesar contenido anterior aunque no se guarde. Los diccionarios grandes pueden exceder el límite de memoria y rechazarse.

Para publicar la extracción sin resultados parciales, pueden coexistir la salida temporal y su copia final: reserva **aproximadamente el doble de la suma extraída**, además del espacio del RAR, de las demás copias y de la reserva de disco configurada. Por defecto cada archivo está limitado a 4 GiB (`MAX_FILE_MB`), el total elegido a 12 GiB (`MAX_QUEUE_MB`), hasta 1.000 archivos por extracción, una lista cifrada de hasta 300.000 bytes y un sobre de selección de hasta 70.000 bytes; nombres extensos pueden obligar a usar lotes menores. También hay límites de RAM y tiempo. Estos valores no son una promesa de que el servidor tenga ese espacio o memoria. El trabajador corta después de unos 15 minutos; una operación puede requerir listado y extracción separados. Si la sesión termina o entra en mantenimiento, no se publica un resultado parcial: vuelve a iniciar la operación tras reanudar, sin repetirla a ciegas si el resultado era incierto.

**Unir partes** está integrado dentro del gestor. En el dispositivo puede cargar las copias seleccionadas o pedirlas al teléfono, ordenar `.001` y unir segmentos MP4/M4A/MP3 compatibles. En el servidor puede unir por streaming hasta 999 partes crudas `.001`, `.002`… de la misma carpeta y el mismo nombre; no remultiplexa segmentos multimedia allí. Para un RAR partido como `archivo.rar.001`, une primero las partes remotas y luego abre el `archivo.rar` resultante. Se rechazan huecos conocidos; si no existe un número total o una huella original, no se puede saber que falte la última parte. Puedes introducir una huella SHA-256 completa opcional, que se envía cifrada y se comprueba antes de guardar. Las partes originales se conservan y la unión se puede deshacer.

### Mover copias entre teléfono, servidor y chat

1. Para importar al espacio local, elige uno o varios archivos. Para enviarlos al servidor, usa **Servidor temporal → Importar desde el móvil** o selecciona un archivo local y usa **Enviar copia al servidor**.
2. Elige el archivo y espera el borrador que prepara la app. **Envíalo tú al chat del bot**, conservando la marca temporal en su texto. La app no recibe una confirmación fiable de que el usuario haya enviado el borrador; espera la confirmación del bot y actualiza el árbol. La autorización de una sola vez caduca y está ligada al remitente y a la sesión. El bot comprueba tamaño y SHA-256 antes de publicar la copia; un adjunto diferente se rechaza y no se elimina el mensaje original.
3. Cada adjunto al servidor debe caber en el límite efectivo por parte indicado. Para archivos mayores, crea primero volúmenes locales del tamaño adecuado y envía cada uno por separado. Los límites reales del proveedor y la codificación del correo pueden ser más estrictos.
4. Desde un trabajo de descarga **listo o terminado**, usa **Copiar descarga al kit**. Se copian las partes sin borrar los originales. Se exige una huella verificable: los segmentos multimedia y volúmenes comprimidos usan sus huellas individuales; las partes crudas pueden usar la huella del conjunto. Si una descarga antigua carece de huellas suficientes, no se copia.
5. Para recibir un archivo remoto en el chat, ábrelo y elige **Enviar copia al chat**. La cola respeta el ajuste de tamaño y los límites del buzón; una copia exportada por el kit no se remultiplexa como vídeo. El seguimiento de entregas y reintentos conserva las limitaciones normales de la cola; ante una respuesta incierta, revisa Descargas y el chat antes de repetir.

### Seguridad y duración

Las contraseñas de comprimidos, las listas y selecciones internas de RAR, las huellas proporcionadas y el contenido de lectura/escritura remota viajan en sobres cifrados con claves efímeras; no se guardan en claro en las actualizaciones WebXDC. Los nombres del árbol del kit, rutas virtuales y metadatos de operación sí se encuentran en las actualizaciones del chat cifrado. Los datos se procesan en memoria y en archivos temporales en los extremos; no se promete borrado criptográfico completo de memoria o disco. Las copias temporales se eliminan al terminar normalmente; tras una interrupción pueden quedar hasta la siguiente operación o la desaparición del servidor.

El almacenamiento local pertenece a una sola instancia y el cliente puede recuperarlo. Conservar la app anterior no migra automáticamente sus datos. El espacio del servidor está en el directorio temporal del trabajo, no forma parte de las copias de seguridad y puede desaparecer al reiniciar o cambiar de corredor. Exporta las copias importantes y verifica su recepción. Las pruebas de Chromium y WebKit son sintéticas: la compatibilidad con dispositivos físicos y versiones reales de WebXDC debe comprobarse por separado.

## English

Open **Downloads → File kit**. **On this device** keeps offline copies inside this mini-app instance; **Temporary server** uses the authorized person's temporary workspace. Selecting a phone file never changes or removes the original.

Expand the horizontally and vertically scrollable tree, choose the destination folder and check entries individually or select all in the current folder. Bulk rename supports prefix, suffix, literal replacement and numbering with a preview, collision checks and undo; suffix and numbering retain extensions. Copy, move, delete and undo/redo operate on copies. Clearing history removes recoverable previous versions. Text editing accepts UTF-8; local text is limited to 4 MiB, remote edits to 70,000 bytes and remote previews to 200,000 bytes. Image and media previews depend on client support; export other binary files to open them elsewhere. There is no hex editor or media trimming/conversion.

Create ZIP/7z archives with optional passwords and volume sizes; open ZIP/7z and read RAR by selecting every volume and the first volume. Existing files are never overwritten. The mobile worker has a user-adjustable 16–128 MiB input/output budget but can use more actual memory; local archive extraction is not selective.

For **selective server RAR extraction**, select the `.rar` or all genuine `.part1.rar`, `.part2.rar`… volumes, designate the first, view the listing and select the files to extract into a new folder. Empty directories are not recreated. Unencrypted names may be visible even with a wrong password; the password is checked during extraction. A wrong password and corrupted encrypted data cannot always be distinguished. Unsafe paths, duplicate names and symbolic/hard links are rejected; per-entry passwords can require separate extractions.

The server uses the separately licensed official **UnRAR 7.30 beta 2** source in `vendor/unrar`, only for unpacking. It streams archive input and selected output through a temporary, network-free, reduced-privilege process. Isolation reduces risk but is not a guarantee. Solid archives may need to process preceding content, and large dictionaries can exceed available memory. Allow roughly twice the selected output size in additional free disk for scratch and atomic copies, plus the input, other copies and the configured disk reserve. Defaults cap one file at 4 GiB (`MAX_FILE_MB`), one selection at 12 GiB (`MAX_QUEUE_MB`), 1,000 files, a 300,000-byte encrypted listing and a 70,000-byte selection envelope; long names can require smaller batches. RAM and time limits also apply. The worker stops after around 15 minutes per run. An interrupted operation does not publish partial output and must be restarted after maintenance; check for an uncertain result before repeating.

**Join parts** is integrated within the kit. On-device, it accepts selected local copies or phone files, orders `.001` fragments and joins compatible MP4/M4A/MP3 segments. The server can stream up to 999 same-folder `.001`, `.002`… raw fragments into a new copy; media remuxing remains on-device. For `archive.rar.001` fragments, join them on the server first, then open the resulting `.rar`. Known gaps are rejected; without a total count or original fingerprint a missing final part cannot be established. An optional full SHA-256 is sent encrypted and checked before publication. Original parts remain and the join can be undone.

To copy a phone file to the server, the app prepares a one-use attachment draft. You must send it to the bot's chat with the marker unchanged; wait for the bot's confirmation. The server checks the chosen file's SHA-256 and size. Each attachment must fit the effective per-part limit; divide larger files first. Finished or ready downloads can be copied when enough hashes are available. To send a server copy to the chat, use the existing queue, which applies the configured mailbox ceilings; check the queue before retrying an uncertain operation.

Archive passwords, RAR member listings and selections, supplied fingerprints, remote text and preview bytes use ephemeral encrypted envelopes. Kit tree names, virtual paths and operation metadata remain in encrypted chat updates. Processing still occurs in endpoint memory and temporary sandbox storage; complete cryptographic erasure is not promised. Temporary copies are normally cleaned after the operation; after a crash they can remain until the next operation or server disappearance. Local storage is per instance and may be reclaimed. Server storage is temporary, is not backed up, and can disappear when the runner changes. Export and verify important copies. Synthetic Chromium/WebKit tests do not establish compatibility with physical Android or iOS devices.
